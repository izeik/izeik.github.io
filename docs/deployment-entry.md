# 发布入口与白屏修复

网站存在自定义Actions发布dist和分支源码发布两条路径。源码入口引用`/src/main.ts`，直接由静态服务器提供时会因模块MIME或TypeScript解析失败而白屏。此前发布还删除了旧哈希脚本，缓存旧HTML的浏览器可能请求到不存在的资源。

现在Vite使用相对资源路径，构建产物既可放在站点根目录，也可由`/dist/`访问。源码入口加载失败时跳转到构建页，开发服务器存在Vite客户端时不跳转；构建HTML不包含此源码回退，避免循环。

构建保留已经发布的哈希资源，并恢复上一版入口脚本。发布时应保留这些缓存兼容文件，不要在复制新dist前删除旧的JS/CSS。

部署设置建议只使用GitHub Actions作为Pages Source；兼容入口保证分支源码路径仍可到达构建页。GitHub Pages为静态托管，重启云端开发服务不会直接重启公开网站，入口修复需要重新构建和发布。

验证：静态源码入口的白屏已在本地实际复现；修复后浏览器检查开发根目录、构建根目录、源码根目录到dist的回退、直接dist访问和缓存旧HTML，均能打开首页，构建页的刷词懒加载和图片也通过。公开域名在当前云端受出站网络策略限制，发布状态以GitHub Actions为准。
